GTLCore 任务国际化工具

运行要求

需要 Python 3.10 或更高版本，不需要安装第三方 Python 包。
在仓库根目录执行下面的命令。带空格的路径需要加引号。
游戏端需要支持此格式的 GTLCore；旧版 FTB Quests 本身不会加载这些 JSON。

框架与现有任务的关系

适配基线是 FTB Quests 2001.4.22。该版本已有 {语言键} 和 JSON Component
translate 的解析能力，但不读取任务目录里的 lang/*.snbt 或本框架的 JSON。
标题、说明等还有显示缓存；仅把中文替换成语言键，不能实现完整的语言切换。

框架保留原生任务结构，增加三层：

  1. 服务器从任务目录读取默认语言和各语言 JSON，按客户端请求同步译文。
     单人游戏同样通过集成服务器处理，客户端与服务器的语言状态分别保存。
  2. 客户端依据 Minecraft 当前语言解析本任务书命名空间的 key，缺译时回退
     默认语言，并刷新 FTB 与 Component 显示缓存。原版和其他模组的语言资源
     不受任务目录内 JSON 覆盖。
  3. 游戏内译文编辑器单独发送“语言、key、打开时的值、新值”。服务器检查
     FTB 编辑权限和旧值，再原子保存对应语言文件，随后通知客户端刷新。

这避免把译文塞进任务对象或把一种语言的文字写回所有玩家共同使用的 SNBT。
两个维护者编辑不同语言或不同 key 不会互相覆盖；同一 key 的过期保存会被拒绝。
服务器上的文件被外部翻译工具修改时，也会要求先重新加载，避免覆盖机翻结果。
重新加载出错时继续使用此前有效的语言数据，并把错误反馈给编辑者。

普通译文修改不触碰任务结构。任务条件、依赖、奖励、进度身份和说明段落顺序
仍由 FTB Quests 管理。编辑段落结构时走原生任务保存流程；其并发语义仍是
FTB 的对象编辑流程，不等同于译文逐 key 的服务器比较并保存。

文件格式

任务结构继续保存在 config/ftbquests/quests 下的原有 SNBT 文件。
语言文件独立保存在该目录的 lang 子目录：

  lang/gtlcore-i18n.json
  lang/zh_cn.json
  lang/en_us.json              可选；没有译文时回退到中文源文

gtlcore-i18n.json 的格式为：

  {
    "format": 1,
    "default_language": "zh_cn",
    "key_prefix": "gtlcore.quest.gtl."
  }

每个语言文件都是 UTF-8 标准 JSON，只有平铺的 key:string：

  {
    "gtlcore.quest.gtl.book.root.title": "格雷科技休闲版",
    "gtlcore.quest.gtl.quest.0123456789abcdef.title": "任务标题",
    "gtlcore.quest.gtl.quest.0123456789abcdef.description.0000": "任务说明"
  }

key 使用对象类型、原有任务对象 ID 和字段名，不使用中文标题或文件名。
book.root 是任务书的保留单例标识。其他对象使用原有的 16 位十六进制 ID。
说明和章节副标题中的四位编号是持久段落 ID：初次迁移时取原始位置；
以后插入新段落会分配新的 ID，不重排已有键。不要为了整理文件重编号。

SNBT 中的普通文字替换为 "{gtlcore.quest.gtl.…}" 引用。
JSON Component 中的文本节点替换为 translate，颜色、点击目标和其他结构保留。
语言文件中只有正文文字，不包含整段 Component JSON、任务依赖或奖励命令。
已有物品自动标题仍使用物品原有语言资源，不会固化为中文。

检查与迁移

只读检查任务规模及文本字段：

  python tools/quest_i18n.py "pack/config/ftbquests/quests"

与另一个任务快照比较文件哈希：

  python tools/quest_i18n.py "pack/config/ftbquests/quests" --compare "old-pack/config/ftbquests/quests"

转换到新的任务目录：

  python tools/quest_i18n.py "pack/config/ftbquests/quests" --output "quest-build/quests"

输出目录必须尚不存在，并且不能与输入目录互相包含。工具从不原地覆盖输入。
迁移结果里的 quests 目录可以作为整合包的 config/ftbquests/quests 进行发布。
修改正在运行的整合包前，应先备份并退出游戏或停止服务器，再部署核对后的目录。
转换前必须确认输入是正在发布的任务版本。转换器只处理提供的文件，不会自动
合入另一份任务包新增的目标；把旧任务树重新部署到较新的服务器会丢失新增内容。
任务更新包另外包含的 kubejs/assets 语言和图片资源也应随该版本保留。

如果需要详细迁移审计，显式指定一个位于输入和输出目录之外的新文件：

  python tools/quest_i18n.py "pack/config/ftbquests/quests" --output "quest-build/quests" --audit "quest-audit.json"

默认不生成审计文件。审计文件含原文、文件路径和哈希，仅供维护者核对，
不应放进发布用的 quests/lang 目录。

迁移保留原始任务 ID、依赖关系、进度身份、物品 NBT、奖励命令及布局。
空行、{@pagebreak} 和 {image:…} 控制行保留在 SNBT 中，因为它们决定
分页和图片布局，不是需要翻译的自然语言。所有改动都通过文本值定位，
并检查反向还原后原始 SNBT 字节一致；Component 另外检查语义结构一致。

重复迁移已转换目录不会重命名已有键。现有 lang/*.json 会被保留并验证。
为已转换任务插入新说明段落后，可再次迁移到另一个新目录来分配新键。
已翻译字段的文字修订应编辑语言文件或使用游戏内译文编辑器，不要把引用
改回普通文字来覆盖旧键。存在冲突时工具会停止，不会猜测应覆盖哪个版本。

升级到新版任务时，以新版完整任务目录作为输入；不要把旧版转换结果直接覆盖
新版任务。可用以下参数从旧的国际化任务目录中复用已有译文：

  python tools/quest_i18n.py "new-pack/config/ftbquests/quests" --output "quest-build/updated" --reuse-translations "old-translated/quests" --audit "quest-upgrade-audit.json"

只有 key 仍存在、且新旧默认语言原文完全相同的目标语言条目才会复用。
原文已改、key 已删除的旧译文会跳过；新目录已有的译文优先，不被旧值覆盖。
默认语言原文始终来自新版任务。审计及命令摘要会分别记录复用、原文变化、
key 删除和新译文已存在的数量。工具不会改动新旧两个输入目录。
此参数只能与 --output 迁移一起使用，两个目录的清单格式、默认语言和
key 前缀必须一致。没有旧译文时不要指定此参数，不会自动生成英文译文。
从旧任务树更新时，任务本身的增删、物品条件、奖励和布局都以新输入为准；
译文复用不合并旧任务定义。发布包额外附带的 kubejs 图片和语言资源也应保留。

机器翻译

导出可以直接交给翻译工具的平铺 JSON：

  python tools/quest_i18n.py "quest-build/quests" --export-job "translation-work/en_us.json" --target-language en_us

生成两个文件：

  translation-work/en_us.json       原文 key:string；只翻译其中的值
  translation-work/en_us.meta.json  源文哈希和语言信息；不要交给机器翻译

告诉翻译工具：保留所有 key，只翻译字符串值；保留 & 颜色/格式码、%s/%d
占位符和 URL；输出合法的平铺 JSON，不添加 Markdown 围栏或额外说明。
翻译后的文件可以覆盖工作目录里的 en_us.json，或另存为 translated.json。
任务目录本身不受影响。不要把 .meta.json 放进任务的 lang 目录。

校验翻译结果并生成可部署的语言文件：

  python tools/quest_i18n.py "quest-build/quests" --import-job "translation-work/en_us.json" --import-output "translation-ready/en_us.json"

如果译文另存了名字，需要显式指向原来的元信息：

  python tools/quest_i18n.py "quest-build/quests" --import-job "translation-work/translated.json" --import-metadata "translation-work/en_us.meta.json" --import-output "translation-ready/en_us.json"

输出路径必须是尚不存在的文件，文件名与目标语言一致，并位于输入任务目录外。
校验通过后，把生成的 en_us.json 部署到任务目录的 lang/en_us.json。
译文可以只包含部分键；缺失键使用源文回退。未翻译的键应省略，不应填空字符串。
原文在导出之后修改过时，导入会停止，要求重新导出并复核，避免把旧译文
默默应用到已经修订的任务说明。

导入检查

工具拒绝重复键、未知键、非字符串值、空译文、被修改的占位符/格式码/URL、
新增的 FTB 页面或图片控制符，以及引用其他任务翻译键的递归文本。
结构校验不能代替人工检查翻译质量；保持原文不变的值会单独计数。

与游戏端一致的限制：

  语言代码：[a-z]{2,8}(?:_[a-z0-9]{2,8}){0,2}，例如 en_us、zh_cn、zh_hans_cn。
  单个语言 JSON：最多 16 MiB。
  单个语言文件：最多 100,000 条。
  单个 key：最多 256 个字符，使用指定前缀及小写字母、数字、下划线、点、横线。
  单条文字：最多 16,384 个 UTF-16 单元；多数 emoji 占两个单元。
  不允许 NUL 或包含 "{gtlcore.quest.gtl." 的递归引用。
  不允许无配对的 Unicode 代理字符，以及包含 "{@" 或 "{image:" 的控制文本。
  整个语言目录：最多 256 种语言，语言文件与清单总共最多 64 MiB。

游戏内维护

开启 FTB Quests 编辑模式，打开任务/章节等对象的原生编辑表单，点击
标题或副标题字段可以直接编辑当前游戏语言的译文：单段文字使用原生 FTB 弹窗，
服务器确认保存成功后关闭；冲突或权限不足时保留输入，不会把语言 key 写成正文。
任务页面的标题快捷编辑同样适用。多段/多节点文字使用完整译文面板。

要编辑另一语言或查看全部文字，点击原生表单中的“任务译文编辑器”条目。
输入语言代码并点击“加载”，左侧按标题、副标题、目标/奖励编号和说明段落选择，
右侧对照源文编辑并保存。搜索框支持查找文字、字段标签及完整 key。
目标语言可以与当前 Minecraft 显示语言不同，不需要切换游戏语言才能翻译。
任务没有自定义标题、继承第一个目标名称时，会显示“标题（来自目标 1）”；
编辑的是原目标的译文，不额外生成一个覆盖自动标题的任务标题。
物品名自动标题仍由对应模组语言资源提供，不会为每个任务复制物品名翻译。

目标类型、右键菜单和“可选目标”等属于 FTB 的界面语言，不属于任务正文语言库。
这些界面随 Minecraft 语言切换；把翻译目标设为 en_us 不会强制把中文界面切为英文。

有 FTB Quests 编辑权限的维护者可在译文编辑界面选择语言和键，修改后保存。
译文保存到服务器/单人任务目录中的相应语言 JSON，其他语言不会被覆盖。
移除某个目标语言的译文后，该键恢复源文回退；源语言条目不能移除。
普通玩家按自己的 Minecraft 语言查看任务，同一服务器的玩家可以使用不同语言。
外部工具更新语言文件后，通过译文界面的重新加载功能载入新文件。
如果文件被其他维护者修改，保存会报告冲突；重新加载后复核再保存。
重新加载过程中，玩家继续看到最近一次完整译文；编辑操作等待新快照，避免
在同步期间显示裸 key 或保存过期内容。返回任务页时也会刷新已缓存的文字。

任务译文编辑器中的“段落与分页”可移动、删除说明段落和插入分页。
移动的是已有引用，语言文件中的段落键不会随位置改变。新增原文段落后，
先保存段落结构，再点击“收集新增文本”将其登记到源语言文件。
任务条件、奖励、布局等结构仍使用原生 FTB Quests 编辑器维护。
原生物品名称等自动标题仍由 Minecraft/对应模组翻译，留空即可保留此行为。

在游戏中复制已经国际化的任务后，先执行译文界面的“收集新增文本”。
系统会按新对象 ID 为同类型对象的旧引用建立独立键，并复制已有的各语言译文，
使后续修改新任务不会连带修改原任务。外部命名空间及显式跨对象类型引用保留。
离线转换器目前保留所有显式语言引用，不自动判断它们是共享引用还是复制遗留；
离线复制 SNBT 的任务仍需在游戏中执行上述收集步骤来重新归属语言键。
